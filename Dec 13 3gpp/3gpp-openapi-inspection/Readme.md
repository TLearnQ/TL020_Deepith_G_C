# 3GPP OpenAPI Inspector (Rel-19) — Parsing & Coverage

## Objective
Parse five OpenAPI (3GPP Rel-19) YAML files and produce endpoint metadata, structured logs, robust API client patterns, and an aggregated coverage summary.

## Repo contents
- `openapi_yaml/` — place the 5 OpenAPI YAML files here.
- `src/parser.py` — parse file -> `metadata/*.metadata.json`
- `src/aggregator.py` — aggregate metadata -> `summary/*`
- `src/client.py` — API client pattern with structured logging and error handling
- `src/logger_setup.py` — JSON structured logging
- `src/errors.py` — APIResponseError
- `metadata/` — generated by parser.py
- `summary/` — generated by aggregator.py

## Quick Start
1. Create virtualenv and install:
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
2. Copy 5 OpenAPI YAML files into `openapi_yaml/`.
3. Run parser:
python src/parser.py
This produces `metadata/<api>.metadata.json`.
4. Run aggregator:
python src/aggregator.py
This produces `summary/coverage_summary.json` and `summary/coverage_summary.md`.
5. Optional: use `src/client.py` to exercise endpoints in a safe mode (no secrets).

## Logging
Structured JSON logs are emitted to stdout via `python-json-logger`. See `src/logger_setup.py`.

## Deliverables
- `metadata/*.metadata.json`
- `summary/coverage_summary.json` and `.md`
- README (this file)
- GitHub repo link

## Notes on security/auth
The parser just extracts declared security schemes (API Key / OAuth2 / HTTP Bearer) found in `components.securitySchemes`. The client implements basic `auth` parameter for requests; do not embed secrets in repo.
